Desain Basis Data Firestore (NoSQL)

Aplikasi: QAYRA FACIAL ANALYZING — by Qayra Make Up
Teknologi: Google Cloud Firestore (NoSQL Document Database) + React + TensorFlow.js (MobileNetV2/TFLite)
Domain: Analisis kondisi kulit wajah klien untuk persiapan makeup acara.

1. Strategi Pemodelan NoSQL

Aplikasi ini menggunakan strategi kombinasi: Referencing + Embedding + Denormalisasi, yang diterapkan pada dua koleksi utama, yaitu users_qayra dan analysis_qayra.

  • Referencing (antar koleksi): Setiap dokumen pada koleksi analysis_qayra menyimpan field userId yang merujuk ke document ID dokumen pada koleksi users_qayra. Pendekatan ini dipilih karena seorang Client dapat memiliki banyak riwayat analisis (relasi one-to-many), sehingga menyematkan seluruh analisis ke dalam dokumen user akan membuat dokumen membengkak. Fungsi getAnalysisByUser(userId) melakukan query where('userId','==',userId) untuk mengambil riwayat milik Client tertentu.
  • Embedding (di dalam dokumen): Hasil inferensi model MobileNetV2 yang bersifat kompleks disematkan langsung di dalam dokumen analisis, karena selalu dibaca bersamaan dengan analisisnya dan tidak pernah di-query secara mandiri. Contoh field tersematkan: array topClasses (objek key/label/probability/rank), array treatmentPriority, array modelOutputRaw, dan objek bersarang preparationProtocol (berisi sub-array 7_days_before, 3_days_before, day_of_makeup).
  • Denormalisasi: Dokumen analysis_qayra menyalin name, email, dan eventDate milik Client pada saat analisis dibuat. Tujuannya agar halaman Hasil Analisis milik Admin dapat menampilkan identitas klien tanpa harus membaca dokumen user satu per satu (mengurangi jumlah pembacaan dokumen Firestore).
Catatan keamanan domain: Autentikasi tidak menggunakan Firebase Authentication, melainkan Firestore-only. Field password disimpan dalam bentuk hash bcrypt di dalam dokumen users_qayra dan tidak pernah dikembalikan ke klien (di-strip oleh stripPassword()).

2. Struktur Koleksi (Collection Structure)

  • users_qayra collection
    • {userId} — contoh: 3kZ9aQpLm2bN7dRfYx1T (auto-ID)
      • name : string — "Salsabila Putri"
      • email : string — "salsabila@gmail.com"
      • password : string (bcrypt hash) — "$2a$10$..."
      • role : string — "user" | "admin"
      • status : string — "active" | "inactive" | "pending"
      • eventDate : string (ISO) — "2026-07-20T00:00:00.000Z"
      • createdAt : string (ISO)
      • updatedAt : string (ISO)
      • lastLoginAt : string (ISO)
  • analysis_qayra collection
    • {analysisId} — contoh: Ab12Cd34Ef56Gh78Ij90 (auto-ID)
      • userId : string → referensi ke users_qayra/{userId} — "3kZ9aQpLm2bN7dRfYx1T"
      • name : string (denormalisasi) — "Salsabila Putri"
      • email : string (denormalisasi) — "salsabila@gmail.com"
      • eventDate : string (denormalisasi)
      • imageUrl : string (base64 dataURL foto)
      • result : string — "Oily Skin"
      • predictedLabel : string — "oily"
      • predictedLabelDisplay : string — "Oily Skin"
      • confidenceScore : number — 0.84
      • modelOutputRaw : number[] — [0.05, 0.03, 0.06, 0.84, 0.02]
      • generatedSummary : string
      • clinicalNotes : string
      • summaryType : string — "single_dominant"
      • primaryClass : string — "oily"
      • secondaryClass : string — "normal"
      • tertiaryClass : string — "acne"
      • clinicalFocus : string
      • treatmentPriority : string[] (embedded array)
      • preparationProtocol : map (embedded)
        • 7_days_before : string[]
        • 3_days_before : string[]
        • day_of_makeup : string[]
      • topClasses : array<map> (embedded) — { key, label, probability, rank }
      • catatan_qayra : string (catatan Admin)
      • createdAt : string (ISO)
      • updatedAt : string (ISO, saat catatan diperbarui)
